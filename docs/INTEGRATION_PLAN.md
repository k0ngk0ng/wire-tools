# 统一仓库改造验收

测试先于新增实现。已有仓库的测试随源码一起迁入，不改变原有测试的来源。

## 目标

一个 Go module、一个 `wirectl` 安装入口、一个版本、一个本地 API 入口和一个发布工作流。CLI 通过本地 API 使用 connect、download、talk，首次调用自动启动运行时；不再把 daemon start/stop 作为使用前提。原协议、安全边界、音频处理和下载引擎保留。

## E2E 失败场景

- 全新目录没有配置、没有进程或遗留 endpoint；帮助和版本不应创建运行时。
- 多个 CLI 同时首次调用；只允许一个 API 实例持有锁，所有请求应连接同一实例。
- endpoint 指向已退出进程；后续调用应恢复，不能要求手动启动。
- endpoint 格式错误、权限错误、非回环地址、伪造令牌、浏览器 Origin；必须拒绝不可信请求。
- HTTP 下载、无效 URL、重复提交、暂停/恢复/移除、失败后查询、重启后状态恢复。
- 某个下载引擎缺失或失败；不能阻止帮助、状态、语音或其他引擎使用。
- 语音未配置、无音频设备、设备离线、首次 call/group/media 请求、已有会话；应返回配置或设备问题，不能要求 daemon start。
- 连接未授权、helper 未安装、重复启动、停止及重新连接；保持系统授权边界。
- CLI 和直接 HTTP 请求观察同一状态；命令取消不能关闭其他调用者的会话。
- 更新包平台错误、校验文件缺失、校验失败、异常归档路径、缺少主程序；安装必须保持原样。
- 成功更新后 CLI 和 API 使用新版本；包管理器安装应由同一个更新命令调用对应包管理器。
- 发布归档必须包含统一程序、对应平台的运行依赖、许可证和可核验校验和；不得上传运行状态或密钥。

## 证据

运行 `make check`。Go 检查日志和 E2E JSON 报告保存在 `.cache/evidence/`，CI 上传相同产物。E2E 使用真实 CLI 子进程、本地 HTTP 传输、真实磁盘文件和独立状态目录；语音 E2E 使用明确标记的测试音频驱动，不代表实机麦克风或公网 NAT 验证。

## Direct 独立铃声输出

先编写 E2E 并确认旧实现失败，再新增实现。失败场景包括：配置和配对丢失本机铃声输出；来电铃声进入听筒、网络或收到音频的录音；接听前发送麦克风或文件音频；按键松开、重复按下导致误接听或立即挂断；接听后铃声不停止；通话语音进入铃声扬声器；铃声设备掉线阻塞通话、错误回退到其他输出或恢复后播放过期铃声；挂断、取消后残留语音或铃声；未设置独立输出时破坏原有单输出配置；同一输出被重复独占打开。

通过统一 CLI、真实本地 API、TCP 配对和 UDP 通话验证状态与两个输出端点的 PCM 电平，保留 JSON、进程日志和 WAV。测试驱动仅用于可重复的软件路由验证，实际两个 USB 设备的听感及物理按键另做实机验收。

Linux USB 型号识别采用针对性隔离测试，失败场景先列为：已支持型号回归、新 `12d1:3a07` 型号未匹配、错误 VID/PID 或无关键盘被匹配。真实 HID 事件和设备拔插仍需硬件证据。

两只 USB 音频设备同时接入时，按键应绑定通话设备。新增隔离测试前先列出：输入与输出分别指向不同 USB 设备；禁用麦克风后按通话输出选择；显式选中的设备掉线时误接管另一只；无效或路径穿越设备 ID；系统默认配置回归；sysfs 链接断开。使用临时 sysfs 目录验证设备归属，不将目录模拟解释为真实按键测试。

已有房间通过 `PATCH /config` 和 `talk devices set` 修改本机音频选择。先覆盖活动会话拒绝变更、空变更和未知字段拒绝、只修改指定字段、房间密钥和成员不变、更改后不自动接通、重新连接后使用新的铃声输出，避免要求用户重建房间。

部署检查发现本机也改接 `SPACETOUCH`。macOS 按键匹配新增实现前先覆盖：CoreAudio UID 的 VID/PID 映射、序列号选择、已有 AB17X 和 USB PnP 回归、无麦克风时按通话输出选择、未知制造商的通用 USB Audio、非 USB 输入、损坏的 UID 和默认配置。原生 HID 连接状态在安装后检查，实体按键动作另由现场验收。

远端 USB 重枚举实际出现声卡 2 变为 1，原数字 ID 会交换通话和铃声设备。稳定 ALSA 标识的隔离测试先列场景：声卡重编号后身份不变；铃声设备缺失时不匹配另一只设备；旧数字 ID 兼容；非 USB 设备及非法 ID 不被错误转换；重复声卡名、无效设备号和路径穿越拒绝。使用 ALSA `CARD` 名称生成稳定本机 ID，并在实际枚举时解析成当前原生设备。设备检查按用户要求保持 0.7 输出静音，不进行拨号、铃声或播放验证。

稳定标识下的静默录音对照发现：系统 `arecord` 能采满 PCM，但现有运行时采集在 2 秒看门狗后离线。保留持续状态失败记录，不能将独立采集通过解释为双工会话已通过。硬件检查只读取现有会话状态，断言输出静音、通话待机及持续采集在线，不播放测试音、不保存实际录音。

用户重新授权发声验收后，反馈来电提示听起来像振动，播放／暂停键未接听。来电铃声的局部 DSP 测试先列失败场景：误用低沉的回铃音、缺失双段节奏、空闲／接通后继续响、铃声进入听筒通道、跨回调重置节奏、改变原有拨号回铃音。先写频谱、节奏和路由测试，再实现来电专用铃声；实体按键先读取匹配 USB 节点的原始 evdev 事件，不能仅以接口在线证明按钮动作通过。

## 硬件插件：SAKSHAT 与 SPACETOUCH

用户要求将树莓派 SAKS 和 Mac mini 听筒控制从 Talk 中分离。保留统一程序、版本和发布流程，插件独立启停和保存状态，仅通过本地 Talk API 控制通话。SAKSHAT 使用已安装的 `sakshat` SDK 子组件，避免调用其全局 GPIO cleanup，也不接管蜂鸣器等无关引脚。

新增实现前先覆盖失败场景：默认未启用即抢占设备；S1 松开／按住／启动已按下时误拨；S2 空闲时误拨；同时按两键拨号；来电不能接听；取消或挂断后 6702 残留；拨号／来电不闪烁或接通后仍闪；禁用插件导致通话结束；硬件失联影响 Talk；恢复后重放旧按键；运行时重启丢失启用状态或自动拨号；不存在的插件、未知字段和非法配置；禁用后 GPIO/数码管未释放；Spacetouch 功能仍依赖 Talk 内部的硬件监听器。

E2E 使用真实统一 CLI、HTTP、TCP 配对、UDP 通话及 SDK 驱动子进程，测试构建明确注入模拟的 SDK/GPIO，保留显示轨迹、进程日志和 JSON 结果。真实树莓派验证 SDK 加载、按钮电平及数码管写入无错误；无人观察时不能宣称数字显示外观或实体按键已验收。

## 在线更新 REST 资产入口回归

1.0.2 实机出现 browser download URL 的 `unexpected EOF`，同一资产的官方 REST API 可正常重定向下载。新增实现前先覆盖：资产 id 缺失、0、负数；REST URL 缺失、异仓库、id 不匹配、query 或 HTTP；browser URL/tag/name 漂移与重复；未使用 `application/octet-stream`；不可信重定向；归档 GitHub 摘要、校验文件 GitHub 摘要、独立归档校验任一失败。测试使用真实归档和安装事务，模拟 browser 入口 EOF 与官方 REST 302；失败不得改写安装。

大包分段回归在新增实现前覆盖：缺失或超限的资产 size，probe/每片 total 不符，无效、重复、越界的 Content-Range，截断或超长片段，分片意外返回 200，内容重复导致最终摘要失败，不可信重定向，调用方取消，signed query 错误脱敏。使用受信测试证书的真实 TLS/HTTP 服务测量最多 8 个独立 HTTP/1.1 TCP，并验证一次 REST 探测后复用官方 CDN URL；probe 返回 200 时验证有界单流 fallback。仅 archive 总预算 20 分钟、POST `/v1/update` 30 分钟，其他资源 5 分钟且保留调用方更短 deadline。

签名链接过期回归先覆盖 8 个并发 401/403/618 合并为一次刷新、持续过期最多 4 次刷新、刷新 probe 的 total 异常不得继续下载。刷新只经原资产 REST URL，必须重新获得同 size 的合法 206；signed query 不进入错误或日志，包括 transport 错误与 HTTP status 文本。最终仍由完整归档的 GitHub 摘要和独立校验决定是否安装。
